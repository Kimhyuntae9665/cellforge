# CELLFORGE 사용법

[README로 돌아가기](../README.md)

처음 열면 **셀 20대 · 지속 생산과 공장 확장** 조건이 준비됩니다. 기본 결과, 편입 없는 결과, 실패·복구를 차례로 확인해 보세요. 모든 수치는 합성 모델의 결과입니다.

## 1. 실행하고 화면 읽기

프로젝트 루트에서 HTTP 서버를 시작합니다.

Windows:

```powershell
python -m http.server 8767 --bind 127.0.0.1
```

macOS / Linux:

```sh
python3 -m http.server 8767 --bind 127.0.0.1
```

[http://127.0.0.1:8767](http://127.0.0.1:8767)을 브라우저에서 엽니다. 파일 더블클릭 대신 서버 주소를 사용하세요. 서버 종료는 `Ctrl+C`입니다.

| 구역 | 하는 일 |
| --- | --- |
| 왼쪽: 생산 목표 | 시나리오, 목표·편입 주기·시간·시드, 생산 계획 컴파일, 공정 선택 |
| 가운데: 3D 공장 | 배치, 완성·편입·생산 자원 수, 경과 시간, 시점 전환 |
| 오른쪽: 셀 검사기 | 자원 상태, 좌표, 추가·제거, 자재, 실패·복구, 결과 저장 |
| 아래: 타임라인 | 재생·초기화·배속·시간 이동·최근 이벤트 |

![전체 화면의 16분 상태](screenshots/01-overview.png)

*기본 20대 확장 조건, 시드 42, 16분. 완성 13대·편입 4대·사용 가능한 생산 자원 13개가 표시됩니다.*

**완성 셀**에는 출하 가능, 설치 중, 편입 완료 셀이 모두 포함됩니다. **공장 편입**은 설치를 마친 제품 수입니다. **활성 조립 자원**은 현재 사용 가능한 생산 자원의 총수로, 그 순간 모두 작업 중이라는 뜻은 아닙니다. 기본 9개 자원에 설치를 마친 편입 자원과 사전 추가 자원이 더해집니다.

## 2. 시간 이동과 공장 둘러보기

1. 아래 **▶**로 재생하고 다시 눌러 일시정지합니다.
2. **배속**을 `1×`, `4×`, `12×`, `30×` 중에서 고릅니다. 배속은 화면 재생 속도이며 공정 시간이나 결과를 바꾸지 않습니다.
3. **시간 슬라이더**를 움직이면 재생이 멈추고 해당 시점의 수량·재고·작업 상태가 표시됩니다.
4. **↺**는 같은 시드와 조건의 0분 상태로 돌아갑니다. 새로운 난수 실험이 아닙니다.
5. 드래그로 회전하고 휠로 확대합니다. **평면**으로 내려다보고 **3D**로 돌아오세요. **전체 공장 보기** 버튼은 전체를 보는 원근 시점으로 전환합니다.
6. 왼쪽 공정 목록 또는 3D 셀 바닥을 누르면 오른쪽 검사기에 해당 자원이 표시됩니다. **편입 위치**는 편입 위치 표시를 전환합니다.

![평면 시점](screenshots/02-top-view.png)

*실제 평면 화면. 배치는 시각적 설계이며 이동 거리·충돌·안전성은 계산하지 않습니다.*

되감으면 아직 설치되지 않은 미래 자원은 숨겨집니다. 로봇 포즈는 작업 진행률의 표현이며 실물 제어·물리 시뮬레이션이 아닙니다.

## 3. 확장 정책과 편입 없는 정책 비교

정확한 비교는 **새로고침한 기본 화면**에서 시작하세요. 수동 추가 자원은 프리셋을 바꿔도 유지되므로 먼저 제거하거나 새로고침해야 합니다.

1. 기본 화면에서 **목표 20대**, **편입 주기 3**, **실행 20분**, **시드 42**를 확인합니다.
2. 시간 슬라이더를 오른쪽 끝으로 옮깁니다. 완성 19대, 편입 6대, 출하 가능 13대, 재공 1대가 기준 결과입니다.
3. 오른쪽 아래 **실행 결과 JSON ↓**으로 결과를 저장합니다. 선택한 시점과 전체 실행 결과가 함께 들어갑니다.
4. **공장 편입 주기**만 `0`으로 바꾸고 **생산 계획 컴파일**을 누릅니다. 입력을 바꾸기만 해서는 새로 계산하지 않습니다.
5. 다시 20분으로 이동하면 완성 15대, 편입 0대, 출하 가능 15대, 재공 5대입니다.

![확장 정책의 20분 종료](screenshots/03-expansion-complete.png)

*추가 초기 설비 없는 확장: 완성 19대 = 출하 가능 13대 + 편입 6대. 설치 중 0대입니다.*

![편입 없는 정책의 20분 종료](screenshots/04-baseline-complete.png)

*편입 주기만 0으로 바꾸면 완성 15대 모두 출하 가능한 상태가 됩니다.*

공통 조건은 자재 20대분, 첫 검사 실패 확률 12%, 설치 시간 45초입니다. 편입 정책은 완성품을 공장 안에서 쓰므로 **총완성 증가와 단기 출하 감소가 동시에 생길 수 있습니다**. 출하 가능 수량은 실제 판매·매출이 아닙니다.

프로젝트 루트에서 자동 비교도 실행할 수 있습니다.

```sh
npm run compare
```

동일 시드의 두 정책을 짝지어 10·20·40분과 1~30 시드를 확인합니다. 입력 변동 확인이며 현장 신뢰구간이 아닙니다.

## 4. 공급 부족과 외부 보충

1. **시나리오 → 자재 공급 부족**을 선택합니다. 6대 주문에 관절·컨트롤러가 3대분만 있는 조건입니다.
2. 20분까지 이동합니다. 3대가 완성되고 3대가 자재를 기다립니다. 자재가 모두 있어야 생산을 시작합니다.
3. **장애 복구**를 누릅니다. 기존 실행을 이어 붙이는 대신 **4분 후 부족분을 외부 공급받는 조건으로 처음부터 다시 실행**합니다.
4. 20분 결과는 완성 6대, 편입 2대, 출하 가능 4대입니다.

![공급 부족 상태](screenshots/05-supply-shortage.png)

*6대 중 3대 완성, 3대 자재 대기. 외부 구매 부품이 없으면 생산을 시작할 수 없습니다.*

![외부 보충 조건의 재실행](screenshots/06-supply-recovered.png)

*부족분을 외부에서 공급받아 6대를 완성합니다. 내부에서 관절·컨트롤러를 만든 것이 아닙니다.*

**공급 중단** 버튼은 관절 6개·컨트롤러 1개라는 더 작은 재고 조건을 적용해 재실행합니다. **자재 공급 부족** 프리셋과 같은 입력이 아니므로 섞어 비교하지 마세요. 자재 보존 규칙은 [MODEL.md](../MODEL.md)에 있습니다.

## 5. 검사 실패와 재작업

1. **검사 실패와 복구** 시나리오를 선택합니다. 셀 2의 첫 검사를 실패시키는 조건입니다.
2. 재생하거나 슬라이더를 움직이며 아래 이벤트 기록을 확인합니다. 이 프리셋에서는 6분 부근의 실패·재작업 경로를 살펴볼 수 있습니다.
3. 첫 검사 실패 제품은 **전자부 점검 → 재검**을 거칩니다. 재검에도 실패하면 격리되어 완료·편입에서 제외됩니다.

![검사 실패와 전자부 재작업](screenshots/07-inspection-rework.png)

*검사 실패 조건의 실제 작업 기록. 재작업은 설정 점검을 가정하며 추가 부품 교체 비용은 계산하지 않습니다.*

**검사 실패 주입**도 처음부터 재실행하는 버튼입니다. 실시간 하드웨어 장애 주입이 아닙니다. **장애 복구**는 강제 첫 검사 실패를 끄고 외부 보충 옵션을 켜므로, 한 변수만 바꾼 비교가 필요하면 입력을 따로 보존하세요.

## 6. 초기 설비 추가와 시각적 배치

1. **프레임·플레이트, 6축 암 스택, 암 통합, 엔드 이펙터, 전자부·배선, 교정·검사** 중 하나를 선택합니다.
2. **＋ 조립 셀 추가**를 누릅니다. 해당 공정 자원이 추가되고 계획이 다시 계산됩니다.
3. 추가 자원을 선택해 **추가 셀 제거**로 삭제할 수 있습니다. 필수 기본 공정 9개는 제거할 수 없습니다.
4. 기본 또는 수동 추가 셀을 선택하고 **X / Z 좌표**를 입력한 뒤 **좌표 적용**을 누르면 배치가 바뀝니다.

![추가 초기 자원과 좌표 변경](screenshots/08-layout-extra-resource.png)

*사전에 구매해 설치한 수동 초기 자원은 생산 실적에 포함하지 않습니다. 좌표 이동은 시각화에만 반영됩니다.*

입고·지그 프린트·출하 공정에는 이 버튼으로 자원을 추가할 수 없습니다. 수동 자원은 최대 12개입니다. 생산 후 편입된 자원은 생산 기록의 결과로서 좌표 편집·제거 대상이 아닙니다.

설비 수 추가는 실제 스케줄 용량을 바꿉니다. **좌표만 옮기는 것은 처리 시간·처리량을 바꾸지 않습니다.** 이동 거리·케이블 길이·물류 동선·충돌·안전 구역은 계산하지 않습니다.

## 7. 저장, 불러오기, 결과·STL 내보내기

상단 **설계 내보내기**는 입력과 배치를 `cellforge-recipe.json`으로 저장합니다. **불러오기**로 그 파일을 선택하면 저장한 조건으로 계획을 다시 계산합니다. 현재 재생 시점을 이어서 복구하는 파일은 아닙니다.

| 버튼 | 파일 | 내용 |
| --- | --- | --- |
| 실행 결과 JSON ↓ | `cellforge-results.json` | 현재 시점·상태, 전체 작업 기록·결과, 일부 실패/복구의 이전 조건 비교 |
| 프레임 STL ↓ | `cellforge-frame.stl` | 가정 치수로 생성한 개념 프레임 |

결과 JSON은 분석용 출력입니다. **불러오기**는 `cellforge.recipe.v2` 설계 레시피를 받으므로 결과 파일을 레시피처럼 불러오지 마세요.

[`example-recipe.json`](../example-recipe.json)에는 **암 통합 공정의 수동 초기 자원 `manual-1` 1개**가 있습니다. [`example-results.json`](../example-results.json)은 그 레시피의 실제 브라우저 내보내기 결과입니다. 추가 설비 없는 기본 비교와 구분하세요.

STL은 밀리미터 단위의 여러 개별 보로 구성한 개념 프레임입니다. 체결·공차·하중·전체 Boolean 합집합·제조 적합성을 검증한 생산용 CAD가 아닙니다.

## 8. 모바일

상단 **공정 · 목표 / 3D 공장 / 셀 · 자재**로 패널을 전환합니다. 입력은 공정·목표, 배치는 3D 공장, 자재·실패·내보내기는 셀·자재 패널에서 조작하세요. 아래 재생 버튼과 슬라이더는 같은 실험을 제어합니다.

![모바일 화면](screenshots/09-mobile.png)

*모바일 크기 실제 화면. 패널을 바꿔 데스크톱과 같은 모델과 결과를 확인합니다.*

## 입력 범위와 오류 처리

| 입력 | 범위 |
| --- | --- |
| 생산 목표 | 2~30대 정수 |
| 편입 주기 | 0~10 정수. 0은 편입 없음 |
| 실험 시간 | 2~120분. 엔진에서 초 단위 정수로 처리 |
| 랜덤 시드 | 0~4,294,967,295 정수 |
| X/Z 좌표 | -15~15m |
| 추가 초기 자원 | 최대 12개 |

레시피에는 화면의 별도 입력칸이 없는 검사 실패 확률(0~0.6), 설치 시간(1~600초), 외부 보충·강제 실패 옵션, 초기 재고도 저장됩니다. 수정했다면 레시피 검증을 통과해야 불러올 수 있습니다.

![잘못된 입력의 오류 처리](screenshots/10-invalid-input.png)

*유효하지 않은 입력을 오류로 표시하고 마지막 유효 조건을 보존합니다.*

UI 입력에는 브라우저 검증이 적용될 수 있고 엔진·레시피는 범위·형식을 추가 검증합니다. 계획 재계산이 실패하면 마지막 유효 조건·배치를 복원하고 재생을 멈춥니다. 잘못된 레시피는 오류를 알리고 적용하지 않습니다.

## 문제 해결

- **모듈 오류·빈 화면:** `file://` 대신 서버 주소를 사용하고 프로젝트 루트에서 서버를 실행했는지 확인하세요.
- **주소를 열 수 없음:** 서버 터미널이 살아 있는지, 주소의 포트가 명령과 같은지 확인하세요. 사용 중인 포트는 번호를 바꿉니다.
- **3D 사용 불가 안내:** WebGL 지원 브라우저에서 다시 엽니다. 3D 초기화가 실패해도 생산 계획·시뮬레이션·내보내기는 사용할 수 있도록 구성되어 있습니다.
- **기준 수치와 다른 결과:** 목표·시드·시간·편입 주기·재고·실패 옵션·추가 자원을 함께 확인하세요. 프리셋은 수동 추가 자원을 유지합니다. 기본 복원은 새로고침이 가장 쉽습니다.
- **목표를 늘렸는데 생산 대기:** 목표 숫자 변경이 초기 재고를 자동으로 늘리지는 않습니다. 필요한 자재와 재고를 프리셋·레시피로 맞추세요.
- **복구 후 0분부터 시작:** 실패·복구 버튼은 새 조건으로 처음부터 다시 계산합니다.
- **좌표를 바꿔도 같은 처리량:** 운반·충돌 시간은 엔진에 포함되지 않습니다.

## 코드 검증

프로젝트 루트에서 Node.js와 npm으로 실행합니다.

```sh
npm test
npm run compare
```

자동 테스트는 12개이며 수량·재고·작업·설치·실패·레시피·STL 규칙을 확인합니다. 실물·PLC·MES·LLM·비전 모델·물리 계산은 연결하지 않았으므로 해당 시스템의 검증 결과가 아닙니다. 상세 규칙은 [MODEL.md](../MODEL.md), 범위는 [VERIFICATION.md](../VERIFICATION.md)를 확인하세요.
